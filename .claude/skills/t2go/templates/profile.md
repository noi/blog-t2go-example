# t2go プロファイル

`t2go` / `t2go-batch` スキル用のプロジェクト固有の設定。人が編集する。隣の知見ファイルは自動で育つ。

## 移植

- 言語ペア: <旧言語> → <新言語>            （例: Perl → Go）
- legacy_test_glob: `<t/**/*.t>`
- new_test_root: `<tests/>`
- 読むべきプロジェクトのテスト規約: `<パス or「なし」>`

## 旧実装か移植済みか

テストが触るコンポーネントが、まだ旧スタックで実装されているかを判定する方法:

- エンドポイント: <例:「ルーティング設定 `<ファイル>` でパスを引く。新クラスタに列挙 = 移植済み、旧クラスタに列挙 *または記載なし*（catch-all）= 旧実装」>
- ワーカー/デーモン: <判定方法>
- それぞれで呼ぶヘルパ: <例: 移植済みは `s.Post`、旧実装は `s.PostLegacy`。`s.RunLegacy` は旧スタックにしか無いワーカーの実行だけに使う>

## コマンド

- 新テストのパッケージを1つ実行する: `test-execution.md` を参照
- lint: `<make lint-diff>`   （0 件が完了条件。CI の入口と同じもの）
- ベースブランチ: `<main>`

## Git / PR の規約

- 単体実行のブランチ: `<user>/t2go-<短縮名>`
- バッチのブランチ接頭辞: `t2go/`
- コミットメッセージ / PR タイトル: `t2go: <旧テストのパス>`
- PR ラベル: `<t2go>`        知見 PR のラベル: `<t2go-knowledge>`
- 知見ブランチ名のパターン: `<*t2go-knowledge*>`
- 新しい worktree にコピーする未追跡ファイル: `<.env, .claude/settings.local.json>`
